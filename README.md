# 映像素材ブラウザ

指定フォルダ直下とサブフォルダを再帰的に走査し、ORB特徴の幾何照合で似た画像や動画の領域をグループにまとめるローカルアプリです。ブラウザから操作し、画像処理は手元のPCで行います。

## 起動

Python 3.10 以上、Node.js、pnpm が必要です。展開したフォルダで実行します。

```sh
python -m venv .venv
```

| OS | 依存関係を入れる |
| --- | --- |
| Windows PowerShell | `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` |
| macOS / Linux | `.venv/bin/python -m pip install -r requirements.txt` |

`pnpm dev` を実行し、ターミナルに表示されるURLをブラウザで開きます。終わるときはターミナルで Ctrl+C を押します。

URLのポート番号とトークンは起動ごとに変わります。再起動後は最新のURLを開いてください。開発者ツールで `/scan` が `0 B` のまま失敗する場合は、まずターミナルでサーバーが動いているかとエラー内容を確認します。`Referrer policy: no-referrer` はこのアプリの通常の設定です。

Windowsでは、ブラウザの接続リセット時にPythonのProactorトランスポートが出す `WinError 10054` を回避するため、HTTPサーバーをSelectorイベントループで実行します。Uvicornのループ自動選択を経由せず、終了時のタスク・イベントループの後片付けは `asyncio.run` に任せます。その他のOSではUvicornの通常の起動方式を使います。

`Unable to create process` と表示される場合は、`.venv` が参照する Python を起動できていません。利用可能な Python で `python -m venv --clear .venv` を実行し、上の手順で依存関係を入れ直してから `pnpm dev` を実行します。`--clear` は既存の仮想環境内を作り直すためのオプションです。

## 使い方

**選択** を押してOS標準のフォルダ選択ダイアログから素材フォルダを選び、**解析する** を押します。絶対パスの直接入力もできます。前回使ったフォルダは次回起動時に復元します。指定フォルダ直下とサブフォルダにある動画・画像を再帰的に読み、シンボリックリンクや Windows のジャンクションはたどりません。

フォルダ選択には Python の tkinter を使います。Windows の通常の Python インストールには同梱されています。Linux ではディストリビューションの `python3-tk` パッケージが必要な場合があります。ダイアログはアプリを起動したPCに表示されます。

類似クラスタを選ぶと、ファイル名・代表一致時刻つきで素材が表示されます。同じクラスタ内では、同じファイルは必ず1枚のカードにまとまり、件数はファイル数です。カードを選ぶと、代表時刻から元の動画を再生するか、画像をプレビューします。詳細には一致領域の切り出しと、保持したすべての一致時刻を段階的に表示します。プレビュー再生は利用中のブラウザが対応する動画形式に限ります。MP4から試せます。

初期画面は「左：クラスタ一覧」「中央：選択したフレームと物体候補」「右：比較と判定根拠」の3列です。画面幅が狭い場合は縦に並びます。中央の番号つき矩形または領域ボタンを選ぶと、その候補の切り出し・座標・サイズ・面積比・ORB特徴点数を確認できます。特徴点は紫で表示し、表示の切り替えと点数制限ができます。「候補の採用・除外理由」では小領域・重複IoU・特徴点不足・上限による除外を確認できます。除外枠は必要なときだけ表示できます。詳細には評価した候補と除外候補の最大80件を記録し、省略した細かな候補の数と全件の理由別集計も表示します。

中央の「このファイルの一致領域・時刻」で、同じファイルの別の一致領域・フレームへ切り替えられます。ほぼ静止した隣接フレームの特徴を再利用した場合は、実際に特徴抽出した保存フレームを表示し、再利用した時刻は再生ボタンに明示します。再利用時刻で新たに物体検出・特徴抽出を実行したようには描画しません。

右側では代表領域からメンバー領域への直接一致を選択し、実際の対応点を線で確認できます。緑はRANSACインライア、赤はアウトライアです。線の表示と本数を変更できます。対応点数、インライア数・率、幾何照合スコア、正規化座標の2×3変換行列、判定しきい値、スコア式を表示します。スコアを認識確率や意味的な類似度としては扱いません。クラスタの代表・所属領域・ファイル・時刻と、直接一致による所属理由を追跡できます。メンバー同士の未検証の一致を追加しません。

「グラフ表示」は独立したモードです。全クラスタの一覧から1クラスタを選択して表示し、一覧のページ番号には連動しません。選択済みのクラスタがあればそれを表示し、未選択なら選択を促します。同じファイルは1ノード、同じファイルの組は1エッジに集約します。ノードで素材の領域を確認し、エッジで集約された個々の直接一致を開けます。枠と線の色は物体クラスタ、線の太さ・透明度は幾何照合スコアです。ノードは136×94pxを基準とし、初期表示で過度に縮小しません。ホイール・拡大縮小ボタン・ドラッグ・全画面表示が使えます。上限は1クラスタあたり500ノード・1600エッジで、到達した場合は明示します。配置はWeb Workerで計算し、既存の解析結果だけを投影します。UMAPなどの2次元類似度マップは未実装です。

元ファイルと元フォルダを書き換えず、物体候補の座標・時刻・ORB特徴量と前回の選択をアプリのデータフォルダに保存します。ファイルサイズ・更新時刻・解析設定のハッシュが一致すれば再利用します。再解析時は特徴量からクラスタを組み直すため、追加・変更・削除が反映されます。キャッシュ形式はversion 4で、従来形式からの更新後は最初の解析時にファイルごとに再生成します。候補数などの設定変更も無効化の対象です。SQLiteには候補IDとフレームの証跡テーブルを追加しました。実際に抽出した480px以下のフレームJPEG・候補座標・除外理由を保存し、隣接フレームで特徴を再利用した時刻は1枚の保存フレームを共有します。元の素材は変更しません。アプリのデータフォルダと重なる場所は指定できません。

通信に一時的に失敗した場合は、自動で進捗確認を再試行します。通常のAPIリクエストは15秒でタイムアウトします。フォルダ選択ダイアログは、選択またはキャンセルするまで待ちます。

## 解析の範囲

動画は原則2秒おきに取得し、長辺480px以内で解析します。画像はそのまま1フレームとして扱います。固定5領域は使用せず、OpenCVのCanny輪郭、複数サイズのモルフォロジー処理、大津の二値化による連結領域から、カテゴリに依存しない矩形の物体候補を作ります。面積・短辺・縦横比とIoUによる重複除去を適用し、ORB特徴点が10個未満の領域を除外します。採用数は初期値8領域で、画面から1〜32に設定できます。特徴点不足を除く前の候補探索数にも上限があります。

Selective Searchも検討しましたが、[OpenCVのximgproc拡張](https://docs.opencv.org/4.x/d6/d6d/classcv_1_1ximgproc_1_1segmentation_1_1SelectiveSearchSegmentation.html)への依存を追加せず、既存のOpenCVだけで動作する輪郭方式を採用しました。SAM・YOLO・GPU・学習済み重みのダウンロードは必須にしていません。これは意味的な物体認識ではなく、見た目のまとまりを探す軽量な領域提案です。低コントラスト、背景との境界が弱い被写体、別角度、短い登場シーンは見逃す場合があります。追加モデルの比較はこの初期方式の実素材評価後に判断します。

32×32の縮小画像で前回抽出フレームとの差分が小さい場合、候補提案とORBの再実行を省略します。その間の2秒ごとの時刻は失わず、同じ領域の時刻リストとして保存します。これは前景追跡ではなく、ほぼ静止したフレームに対する再利用です。

小さな画像ハッシュの索引で候補を絞り、1領域あたり最大16代表とのみORB照合します。索引のバケットにも上限があり、全領域間の総当たりはしません。ORBの距離比テスト、対応点の重複排除、RANSACによる幾何検証を行います。対応点10以上、インライア9以上かつ55%以上、両画像での対応点の広がりを条件にします。スコアはインライア率と数から求める0〜1の指標で、認識確率ではありません。近似索引なので候補の見逃しはあり得ます。

`Region`は抽出領域とORB特徴量、`ObjectRegion`は所属ファイルを伴う領域、`Match`は直接照合の対応点・インライア・スコア、`Cluster`は領域と一致関係を保持します。クラスタへの追加は最初の代表領域との直接一致が必須です。A–B、B–Cだけを根拠にAとCを統合しません。同じファイル内の異なる物体も、ファイルが同じという理由では統合しません。別ファイル間の一致、または同一動画内で4秒以上離れた再登場があるクラスタを表示します。

## テスト

UIの回帰テストは `pnpm test` で実行します。Python側は、依存関係を入れた仮想環境の Python で `-m unittest discover -s tests -v` を実行します。

Chrome/Edge/Chromiumが利用できる場合は、まず依存関係を入れたPythonで `tests/export_analysis_fixture.py --folder "検証する素材フォルダ"` を実行します。フォルダを省略すると合成画像を使います。実際のOpenCV処理・API出力と保存フレームをローカルに書き出した後、`pnpm test:browser` で画面を検証できます。必要なら `ORB_BROWSER` に実行ファイルのパスを指定します。ブラウザ試験は矩形・ORB座標・対応線の端点と色を記録データと照合し、除外理由・ファイル集約・グラフ選択・空結果も確認します。126件を追加したカタログの操作試験は表示負荷の検証用で、実際の物体検出結果としては使用しません。画像・JSON・スクリーンショットは `node_modules` 以下に保存します。

## 解析詳細API

通常の `/status`・`/group`・`/graph` には特徴点や対応点の配列を含めません。以下は選択時に取得します。各URLの先頭には起動時のトークンが付きます。

| API | 内容 |
| --- | --- |
| `/frame/{generation}/{file_id}?seconds=...` | 保存フレームの寸法・候補ID・採否・理由・IoU・特徴点数・領域ID |
| `/frame-image/{generation}/{file_id}?seconds=...` | 実際に特徴抽出したフレームの保存JPEG |
| `/region/{generation}/{region_id}` | 所属ファイル・時刻・座標・クラスタ・実際のORB座標 |
| `/cluster/{generation}/{cluster_id}/evidence?region=...&offset=...` | 代表領域・形成方針・所属領域・直接一致（24件ずつ） |
| `/match/{generation}/{cluster_id}/{source}/{target}` | 実際の対応点インデックス・距離・インライア判定・RANSAC変換行列・条件・スコア式 |

矩形座標はフレーム内、特徴点と変換行列はそれぞれの切り出し領域内の正規化座標です。可視化時の再検出やRANSAC再計算はしません。キャッシュから特徴を読み込んだ再解析では、クラスタ照合時に生成した一致証跡をその解析世代の結果として保持します。

## 計測

画面と `/status` の `metrics` で経過時間、キャッシュ再利用数、抽出領域数、隣接フレームの再利用数、照合数を確認できます。APIには領域提案・ORB・幾何照合の処理時間も含まれます。

依存関係を入れたPythonで `benchmark.py --output benchmark-synthetic.json` を実行すると、正解ペア付きの合成画像6枚で固定5領域と新方式を比較します。実素材では `benchmark.py --folder "素材フォルダ" --limit 6 --frames 6 --repeats 3 --output benchmark-real.json` とします。動画は1本あたり先頭6サンプルまで、各方式3回の中央値を記録します。両方式とも特徴キャッシュを使わず、証跡の生成とフレームJPEG化を含め、同じ新照合・クラスタ処理を使うことで領域抽出方式の差を比較します（SQLite書き込み時間は除外）。

精度評価には `--labels labels.json` を指定できます。形式は `{"positive_pairs": [["a.jpg", "b.jpg"]]}` で、対象ファイル内の他の組を負例とします。ラベルがない実素材に精度数値は付けません。合成データの精度を実素材へ一般化しないでください。計測結果は [合成データ](benchmark-synthetic.json) と [高知フォルダの写真6枚](benchmark-real.json) に記録しています。
